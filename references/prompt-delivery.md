# 三项式完整时间线提示词

## 输出约定

正式提示词只放在一个代码块中，按顺序写“画面内容、时间线、全局约束”三项，不加前言、素材对应、人物设定、环境描写、参数清单、分镜表、理论分析或结语。一个单元总时长4–30秒，内部可以切镜，不等于一镜到底。

先分析每个角色的主动动势、弹性和表情强度，再设计整段表演，把关键表演节拍转成镜头强弱、景别与运动节奏后安排分镜，最后整合进时间线；分析表留在内部，不额外增加分析项。用户另外明确要求查看过程时再展示。

## 结构与时间检查脚本

原版内置 `scripts/validate_prompt.py`，仅依赖 Python 3 标准库。根据实际安装位置解析技能目录，不依赖当前工作目录。示例调用：

```shell
python "<技能目录>/scripts/validate_prompt.py" "<UTF-8提示词文件>" --duration 14 --require-code-block
```

`--duration` 填用户已确认的总秒数，未指定时可省略。默认接受纯提示词正文或一个完整代码块；检查最终交付稿时加 `--require-code-block`。路径为 `-` 或省略时从 UTF-8 标准输入读取；也支持带 BOM 的 UTF-8 文件。脚本不创建或修改文件，候选稿可在系统临时目录暂存。

结果为 JSON，含 `ok`、`errors`、错误行号、实际终点和段数。退出码：`0` 表示结构与时间通过，`1` 表示内容检查不通过，`2` 表示输入或调用失败。检查三项标题的数量与顺序、非空正文、独立声音栏目、单代码块包装、时间线标题后直接接时间码、有效区间、从0开始、空档／重叠／重置、4–30秒总时长及与标题或指定时长的一致性。内部单段可短于4秒；用十进制精确比较小数时间。

它不能识别任意自然语言是否偷偷新增了栏目或把全局限制夹入动作正文，也不能判断一个动作是否真的有时间演完。这些语义问题以及动态张力、弹性、运镜效果仍由模型依据下面的门槛复核。不得把 JSON 的 `ok` 解释成“迪士尼动画质量合格”。修订后检查最终文本，错误未解决不声称通过。

维护脚本后可运行 `python -B "<技能目录>/scripts/test_validate_prompt.py"`，验证正常输入、时间错误、格式错误、UTF-8输入和随包示例。这是开发回归检查，不需要每次写提示词都运行。

## 画面内容

用一段简短情节概括点明：在哪个场景、有哪些出场角色、发生什么、最后怎样。人、动物及参与行动的其他角色都需交代；不因为蝴蝶等角色体型小就遗漏。

用户通过参考图控制人物形象和环境。只用“奶奶、小猫、蝴蝶”“院子”等必要称呼，不复述衣服、毛色、长相、年龄、建筑样式、陈设、季节光色或材质渲染。不要另写“图1作为场景、图2作为角色”，也不添加未指定的颜色与外形。

场景名称与动作必需的空间关系可以保留。例如“从院门跑到屋檐下”“前爪压住竹匾边缘”属于叙事与动作条件；一长段房屋、花草、夕阳和衣着说明属于应省略的静态描写。

## 时间线

- 标题可注明总时长，如“时间线（20秒）”，不另设参数项。标题后直接进入首个时间码，不在时间线前或标题下插入全片约束段落。
- 使用`[00:00–00:03]`形式，可含小数秒。从0连续写至终点，无空档、无重叠，末尾等于本单元总时长。
- 每段融合动作、表情、预备、重心、受力、跟随、节奏和摄影。用具体动词、方向、速度与先后，不用“迪士尼风格”或“电影感”代替可见设计。
- 对主要动作保留选定的动态细节：发力与形变部位、滞后方向、越过终点后的回弹，以及动作间的停顿与爆发。不能在压缩文字时只剩“跑、跳、摔、抱”等情节梗概，或一律用“轻微、自然”抹平动画表演强度。
- 逐角色核对其各段动作是否达到内部设定：强动势软角色的所有适用大动作都有明显拉扯、错峰与回弹，弱动势角色以眼神、手部和稳定重心呈现生命力。不在输出中堆“强动势／弹性等级”标签，直接写出各自不同的动作效果。
- 腹部和面颊的肉如何随跑步抖动、转弯时向外侧偏移、停止后如何弹回，属于动态设计，可以写；毛色、服装和静态身体介绍仍省略。动态细节不是对参考图形象的重复描述。
- 使用慢动作时，在同一时间线明确进入和恢复常速的时刻、要看清的弹性过程；所有区间仍为最终播放时间。快切与慢动作服务具体表演，不作为固定模板。
- 慢动作末尾与下一段开头必须共享同一动作状态：从当前肢体位置沿原方向继续，让尚未完成的挥动、接触或扫空及惯性响应可见。下一动作可借余势衔接，预备与回弹可重叠，不强加“做完—停稳—再做”的固定节拍。用户要求接完某动作时保留其剩余行程；要求连续接镜时延续原构图，再按观看需要调整取景，不直接跳到已完成姿势，不重复起手。
- 保留景别、机位、运镜、焦点和切镜；必要时写服务动作阅读的光影，不重新描写静态环境和美术风格。
- 强动态段落把摄影重音写成过程：什么动作触发、朝哪里、怎样加速或减速、起止景别、到位读清什么。甩摇不能只给名称，极特写不能包办全身；弱动势关怀段可主动稳定并延长阅读。镜头强弱与角色强度有联系，但不能机械一致。
- 慢动作、相机移动和剪辑分别写清；可写“场内动作进入慢镜，镜头迅速推至面颊和前爪，落稳看清拉扯，随后恢复常速”，不能只有腾空漂浮却无局部强调。所有动作继续占用同一全局播放时间。
- 切镜时直接写“切至”，时间继续累加，不重新从0计时，不拆为独立提示词。连续运镜阶段不写“切至”。
- 内部镜头可短于4秒，4–30秒限制的是整个单元。用户指定20秒就写20秒，不自动扩至30秒。
- 内容过多先减少重复动作与非必要停留，不能容纳关键事件时询问情节取舍；不偷偷超时、删关键事件或自动拆单元。
- 图像用途、人物对应、比例、材质及光向仍需在内部读取和检查。不复述参考图不等于忽略参考图；切镜后不重置身份、道具状态或动作进度。
- 4–30秒是技能写作规范，不是所有视频平台的能力保证。

## 动态表现的交付门槛

本节检查最终提示词实际写出了什么，不将内部分析、原则名称或强度标签计为完成。按完整动作验收，动作可跨连续镜头，不要求每个小时间段重复所有阶段。

1. **张力要有可见的对抗。** 对主动蓄力的大动作，说明意图朝哪里、支撑或身体怎样暂时收住这股力，例如目光与爪尖已经向前，而肩背向后收、身体压低变宽。不能只写“凶狠、紧张、充满张力”。张力也可来自克制的姿态和节奏，不要求所有角色大形变。
2. **弹性要有不同的关键轮廓。** 对强弹性角色，至少能从本次主要动作辨认出受力前后不同的姿势，如压低变宽到蹬直伸长，再到接触后的挤压恢复；说明哪一处维持支撑、哪一处先动。只有位移、上下起伏或附加一句“弹一下”不够。突发反射不强补预备，形变服从角色结构与接触因果。
3. **错峰与回弹要能区分动作。** 写出具体部位、方向与先后；转弯向外拖曳、急停继续前冲、提起时向下滞留不能通篇套同一句。只保留当前最有辨识度的一两处响应，不让每个部位同频晃动。
4. **关键停顿要真的占时间。** 对承载蓄力、顿悟或喜剧反应的停顿，写出近似播放长度，或给出清楚子区间，说明主体停在哪里、什么仍在动、何事触发爆发。长度按情节确定，例如“爪悬住约0.3秒，尾尖收住后突然拍下”，不能把“半拍”当所有情境的固定值。其时长包含在当前区间，不额外加时；不把所有动作都插入停顿。
5. **动态句子先成立，再配摄影。** 景别和运镜围绕当前形变或反应的可见性安排。摄影重音须写出起幅与落幅的画面差异、冲击速度及落点阅读时间，例如“由上半身在约0.2秒内急推到猫眼与悬爪占满画面，再停住约0.3秒”。不能只在动作末尾附上“快速跟拍”，或每段都套相同的推近与刹停。10秒等紧凑段落先保证关键表演有阅读时间；若一秒内安排多个需要依次读清的表情、松手、起飞、摇镜、落点，应删去次要细节或调整分配，不靠继续堆字解决。快切与甩摇仍可有力使用，但要有清楚重音和落点。
6. **内部对照检查，不输出原则清单。** 为适用的主要动作找到最终文字中的关键姿势、受力形变、节奏反差及摄影可见性证据；与角色分级不符就重写。若删掉“弹性、夸张、停顿”等形容词后仍只剩跑、跳、抓、喊的情节名称，视为未完成。写“明显压扁、突然绷长、大幅拖向外侧”等具体强度是允许的，不因简洁要求自动弱化。

原则是设计依据，不要求输出十二个标题。以下强动势与弱动势示例用于校准不同表现强度，不把其中的角色、镜数、停顿长度或动作套路设成通用默认。

不输出声音设计栏目，不编排独立音效时间表，也不把整套音效搬进其余栏目。用户指定且与剧情相关的对白、叫声或发声前截断保留在对应时间段；删除该栏目不等于全片静音。

## 全局约束

固定为第三项，紧接时间线之后，仍在同一个代码块中。汇总本次贯穿全段的约束：参考场景与背景连续性、允许的机位和取景范围、遮挡与可见部位、角色与道具一致性，以及无背景音乐、无旁白、无额外对白等声音限制。

- 只写本次明确要求或维持已确定方案所必需的限制。正面机位、禁止全身、单一背景等是案例条件，不是所有剧情的默认值；用户要求配乐或对白时不得写相冲突的禁用项。
- 不在画面内容和时间线前另放约束段落，不将整段限制重复粘贴到每个时间码。时间线保留该拍实际发生的动作与观看方式，例如“正面急推到猫脸与红爪同框”，无需每段重复“不切侧面”。
- 具体时刻的停顿、慢动作起止及用户指定的对白、发声或结尾截断仍属于时间线，不能只放成末尾抽象禁令。
- 背景连续不等于禁止透视与景别变化；道具被打翻等剧情引起的状态变化仍应发生。约束应与动作因果相容。

## 强动势示例：10秒内的偷袭、扑空与疼痛反应

假设场景图、肥猫与正在烹饪的鹦鹉参考已齐备，用户要求9:16、10秒：猫偷袭，鹦鹉逃走，猫打翻锅并烫红爪子，疼叫一声。内部判断猫的潜伏段克制、扑抓及疼痛段强动势强弹性；鹦鹉烹饪中等动势、逃跑突然增强，羽毛跟随但躯干不采用猫式甩肉。交付示例：

```text
画面内容
9:16竖屏。灶台前，鹦鹉专心烹饪，肥猫从背后探头偷袭。鹦鹉及时飞走，猫爪扑空打翻热锅，被烫红后疼得大叫一声“喵”。

时间线（10秒）
[00:00–00:02]
中近景，鹦鹉搅拌锅中食物，完全没有回头。身后的肥猫先露出眼睛，再缓缓抬头，目光凶狠地钉住鹦鹉；头停住，面颊才向上挤一下再落回。镜头轻推，将猫眼与毫无察觉的鹦鹉同框。

[00:02–00:03.3]
切侧面中景。肥猫爪尖朝鹦鹉伸，肩背却明显向后收，胸腹压低、横向挤宽，形成前伸与后拉的对抗。先看清压缩姿势，随后相机在约0.2秒内沿猫脸侧前方急推，由上半身冲到眼睛与悬爪占满画面。最后约0.3秒，相机与猫爪同时停住，只有腹部最后一点余晃收下去，紧盯鹦鹉的眼睛一动不动。

[00:03.3–00:04.6]
切鹦鹉近景，猫爪仍在它身后可辨的位置。鹦鹉瞥见猫爪，身体猛缩、眼睛睁圆，松开搅拌器落回锅中；脚离开锅柄，双翼下压，身体突然冲向画面右上方，尾羽向下拖后才甩起追上。相机迟一瞬才沿右上方快速甩摇，鹦鹉已经抢先飞出画框；在它刚离开的空位刹住约0.15秒，强调肥猫这一抓落了空。

[00:04.6–00:06.2]
切侧面中景，猫、爪与锅同框。肥猫从压低变宽的姿势突然绷开，肩背带着右爪向前下方拍出，胸腹软肉还拖在后面，随后猛地追上。相机沿落爪方向短促向下俯摇，从脸与举爪的构图转到右爪和锅沿占据画面下半部，并先停在接触位置；猫爪随后擦压热锅沿，锅被推离支撑翻倒，肉垫受压、锅翻和食物洒出都在稳定画面中看清。

[00:06.2–00:07.5]
切肥猫脸与前胸近景。它猛抽右爪，肩膀先缩回，胸腹却继续向前涌，挤向收拢的前肢再弹回。肥猫把烫红的肉垫举到眼前，相机保持不动，让爪子自己进入前景；主体愣住约0.3秒，只有两颊完成余动。随后眼睛骤圆，嘴巴张开，红爪与表情始终同框。

[00:07.5–00:10]
一声“喵”突然爆发！肥猫后腿蹬直，身体从蜷缩的一团猛地拔长，红爪甩到高处，腹部与两颊却向下拖，随后才弹起追上。叫声起音时，相机在约0.3秒内急速后撤并略向上调整朝向，从脸与前胸近景猛然打开到中全景，绷长的整个姿势突然显露；到位立即停稳。猫落回原支撑，身体压低变宽、软肉下坠再回弹；镜头保持，让余动与刚才的快速拉开形成反差。最后猫护住右爪，恼怒瞪向鹦鹉逃走的方向。


全局约束
角色身份与场景空间保持连续，道具状态随接触和受力变化。
无背景音乐、无旁白及其他对白。
```

本例主动为蓄力和顿悟分配阅读时间，强度来自姿势、受力与快慢差。生成效果仍受模型执行影响；时间码和描述完整不等于成片已验证。

## 弱动势示例：一个8秒单元内完成接球与放球

假设用户已提供场景图、机器人角色图和情节，要求机器人在桌前接住滚来的球并放回桌面，8秒，无对白。先在内部设计手掌迎球、接触后回收缓冲、握稳下降、触桌松手，再安排前半段中景、后半段手部近景。交付如下：

```text
画面内容
桌前，机器人接住沿桌面滚来的球，再将球轻轻放回桌面，松手后球停稳。

时间线（8秒）
[00:00–00:04]
固定中景，让机器人上身、右手与球的滚动路径同框。球滚近时，右手掌先迎向来球，肩臂稍向前伸；接触后手臂沿来球方向小幅回收，肘部弯曲，使球随手逐渐减速。最后稳稳握住，关节完成收势。

[00:04–00:08]
切至同侧的右手与球的近景，完整保留桌面接触区域。手沿短弧线下降，接近桌面时减速；球底触桌、重量转移后，手指逐渐松开。确认球稳定，右手才平稳离开。结束时球静止在桌面。


全局约束
机器人、球和桌面的尺度与接触关系保持连续。
无对白、无背景音乐、无旁白。
```

迭代时保留有效设计，返回三项齐全的整个单元，不交付局部镜头补丁。案例中的时长、镜数、角色和道具不是通用模板要求。
